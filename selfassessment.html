Database Design and Data Management

Database design is one of the clearest connections between my professional experience and my computer science education. As a Senior Data Analyst, I understand how much reporting and analysis depend on accurate, organized, and accessible information. The Computer Science program helped me build on that experience by teaching me more about designing the databases and processes responsible for managing data.

My capstone application uses a relational SQLite database with five interconnected tables: Users, Goals, WorkoutHistory, WorkoutEntries, and Recommendations. The database uses primary keys, foreign keys, validation constraints, indexes, and cascading relationships to organize information and maintain consistency. Records connect through user_id, allowing the application to associate goals and history with the appropriate account.

The WorkoutHistory table stores a date, weight, and step count for each entry. The application supports the four primary CRUD operations: users can create records, view their history, update existing information, and delete records. The history view retrieves records belonging to the signed-in user and displays the newest entries first, making recent information easy to access.

I also incorporated validation to improve data integrity. Weight values must be greater than zero, step counts cannot be negative, required text fields cannot be empty, and dates must follow the expected format and represent valid calendar dates. These controls help prevent invalid information from being saved and reduce the risk of problems later in the application's processing.

This work reinforced the importance of designing databases around the information an application needs to manage. It also showed me how database structure, validation, and queries influence the reliability of the entire system. These are lessons I can apply to larger data environments, where inconsistent records or poorly designed data structures can affect reporting, analysis, and business decisions.

As I pursue more advanced technical roles, I want to apply this knowledge to more complex systems. Security

The Computer Science program also strengthened my understanding of application security and the importance of protecting information throughout the development process. Applications that manage user accounts and personal information must consider authentication, credential storage, input validation, and access to individual records. These protections should be part of the design rather than added only after a problem occurs.

In my enhanced application, passwords are processed using SHA-256 before being stored in the database. The application stores a password_hash value instead of the original plaintext password. During login, the entered password is processed using the same hashing method and compared with the stored hash. This demonstrates the basic principle of validating credentials without storing the original password in readable form.

The application also uses account-specific access controls. After a user authenticates, the application stores that user's database ID in the active session and passes it to database operations. Goals, weight history, and other account-related information are retrieved or modified using the appropriate user identifier. Update and delete operations use both the record ID and user ID when selecting records, helping prevent one account from modifying another account's information through those operations.

Developing these features increased my awareness of authentication, data privacy, input validation, and the importance of limiting access to information. It also helped me understand that implementing a security feature does not automatically make the entire application secure. The implementation must be evaluated in the context of the threats it is intended to address.

For example, SHA-256 alone is not an appropriate password-storage solution for a production application because it is a fast-hashing algorithm and does not provide the protections offered by password-specific hashing methods. Production implementation should use an established adaptive password-hashing algorithm, such as Argon2id, bcrypt, or PBKDF2, with appropriate unique salts and parameters. Recognizing this limitation is an important part of my development as a computer science professional. I want to build applications that function correctly while also following security practices appropriate to their intended use.
